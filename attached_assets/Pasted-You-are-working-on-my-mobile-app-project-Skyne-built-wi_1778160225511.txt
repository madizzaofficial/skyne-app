FEATURE 2 — SHARE EXTENSION / SHARE INTENT FLOW
==================================================

Goal:
When a user is on a product page from any website such as Sephora, Atida, Amazon, YesStyle, Stylevana, Nocibé, Notino, etc., they should be able to tap Share → Skyne.

The app should receive the shared URL and open an analysis screen.

Important:
- Implement this in a way compatible with Expo / React Native.
- If the current project uses Expo Managed Workflow, check whether a config plugin or a native module is required.
- If full native Share Extension cannot be completed inside the current Expo setup, implement the best possible foundation:
  - deep link handling
  - shared URL intake screen
  - parsing pipeline
  - clear TODO comments for native share extension configuration
- Do not fake a working native share extension if it requires prebuild/native configuration.

Required behavior:
1. User shares a URL to the app.
2. App opens the ProductImportAnalysis screen.
3. The screen receives:
   - sharedUrl
   - optional sharedText
4. The app displays:
   - "Analyse du produit en cours..."
   - the URL
   - loading state
5. The app tries to extract product info from the URL.

Create a service:
src/services/import/
  sharedProductImportService.ts

This service should expose:
- parseSharedProductInput(input: { url?: string; text?: string })
- extractUrlFromSharedText(text: string)
- detectRetailerFromUrl(url: string)
- fetchProductPageMetadata(url: string)
- normalizeImportedProduct(rawData)

For now:
- Implement URL detection.
- Implement retailer detection for:
  - amazon
  - sephora
  - atida
  - nocibe
  - notino
  - yesstyle
  - stylevana
  - other
- Do NOT scrape aggressively from the mobile app.
- Create a placeholder backend call function:
  analyzeProductFromUrl(url: string)
This function should be clearly separated so later it can call a backend endpoint.

Important architecture note:
Product page scraping should happen on the backend, not inside the mobile app, because:
- CORS issues
- anti-bot protections
- HTML parsing instability
- security
- app performance

So create a frontend-ready flow, but keep scraping/backend extraction behind a service abstraction.

Create or update navigation:
- Add ProductImportAnalysis screen.
- Add route that supports deep links like:
  skyne://import-product?url=...
  skyne://analyze-url?url=...
- If Expo Router is used, create the appropriate route file.
- If React Navigation is used, add the screen to the navigator.

Add deep linking config if missing:
- scheme: "skyne"
- support URL handling on app launch and when app is already open.

If the app already has a product analysis screen, reuse it instead of creating duplicate logic.

Expected UX:
- If URL is valid:
  - show retailer detected
  - show "Produit détecté depuis Sephora/Amazon/etc."
  - show button "Analyser ce produit"
  - then display the ProductAnalysisResult
- If URL is invalid:
  - show a clean error state
- If product ingredients cannot be extracted yet:
  - show a fallback state asking user to paste ingredients manually
  - provide a text area/input for ingredients
  - allow analysis from pasted ingredients

Manual fallback:
Create a component:
src/components/product/ManualIngredientsInput.tsx

It should allow:
- product name optional
- brand optional
- ingredients text required
- button "Analyser les ingrédients"

Then use productAnalysisService to generate rule-based analysis.
