Context:
Skyne is a skincare/cosmetic product analysis app. Users can scan a barcode, search a product, share a product page, view product details, analyze ingredients, and contribute missing product information.

PHASE 5 — PRODUCT LOOKUP LOGIC
==================================================

Implement:

lookupProductByBarcode(barcode: string): Promise<ProductLookupResult>

Behavior:
1. Clean and validate barcode.
2. Search local PostgreSQL by barcode.
3. If product exists and completeness_score >= 70:
   - return local product.
4. If product exists but is incomplete:
   - call Open Beauty Facts API to try to enrich it.
5. If product is missing:
   - call Open Beauty Facts API.
6. If API returns a product:
   - normalize it.
   - merge safely with local product if it exists.
   - save/update local DB.
   - recompute completeness_score.
   - run or fetch cached analysis if ingredients exist.
   - return product.
7. If API does not find product:
   - return not found result with needsContribution = true.
8. Never call the Open Beauty Facts API directly from the mobile client.

Implement result shape:

ProductLookupResult:
- product: Product | null
- source: "local" | "open_beauty_facts_api" | "not_found"
- needsContribution: boolean
- missingFields: string[]
- message: string
- analysis?: ProductAnalysisResult

==================================================
PHASE 6 — SEARCH LOGIC
==================================================

Implement:

searchProducts(query: string): Promise<ProductSearchResult[]>

Behavior:
1. Search local DB first.
2. If query length < 3, do not call external API.
3. If local results are enough, return them.
4. If local results are weak or empty, call Open Beauty Facts search API.
5. Normalize useful API results.
6. Save them locally.
7. Return merged deduplicated results.
8. Do not call API on every keystroke; frontend must debounce.
9. Backend should be safe against spam.

PHASE 9 — SAFE MERGE RULES
==================================================

When merging API data into an existing local product:

Do:
- keep verified local data over external API data
- fill missing fields from API
- update stale external fields if local data is not verified
- keep raw API JSON
- recompute completeness_score

Do NOT:
- overwrite verified fields
- replace non-empty ingredients with empty/null
- replace existing images with null
- overwrite user/admin reviewed data blindly
